# Samurai

Samurai 1.3 is the official stable C99/POSIX Ninja-compatible build tool from
`michaelforney/samurai`. The fixed source commit is
`4288e71812493cb21b54ef23642a13214f44885f`; the 33,459-byte archive SHA-256 is
`c1e5052f438034bd2eb3cc6cba020952110c4b3411964c7b06267b05d04a64e3`.
Arch stable extra supplies discovery lineage, not the build source or a target
provider claim. All 37 inert source members matched upstream Git blob IDs/modes.

The recipe retains the complete original `all: samu` build, 13 C objects,
`OS=posix`, C99 warning flags, `LDLIBS=-lrt`, and default executable/manual
installation. It relocates the supported PREFIX/BINDIR/MANDIR to RPM paths.
The upstream opt-in `HAVE_GETLOADAVG` feature remains default-off; no feature or
original test is removed. `samu --version` intentionally prints supported Ninja
language `1.9.0`; the RPM package version is `1.3`.

`ISC AND Apache-2.0 AND MIT` reflects the unchanged complete upstream LICENSE:
Forney ISC, Ninja reference-source Apache-2.0, and Myrddin/musl MIT notices.
Both packages carry that entire file. `samurai-tests` also retains the exact
unchanged official archive and authored Apache-2.0 functional QA. No external
packaging recipe or upstream source code was executed during local preparation.

The captured upstream tree declares no tests, test directory, or test/check
Makefile target; its five CI configurations only build. The new downstream QA
is not an upstream suite. `%check` exercises the just-built and staged executable
using the same substantive offline checks as installed smoke: fixed archive,
notices/manual/README, supported language version, Ninja manifests, incremental
and command-change rebuilds, include/subninja scope, phony/pool dependencies,
response files, GCC-format depfiles/dependency log, all six tools, dry runs,
cleaning, and rejection/failure boundaries. Each subprocess has a deadline;
fresh temporary directories prevent stale output from passing checks. Tests use
Python standard-library code and POSIX shell builtins, not network or a compiler.
They neither certify native RISC-V behavior nor timing/performance/security.

Build dependencies are gcc, make, glibc-devel, tar, gzip, coreutils, python3 and
binutils. The runtime requires bash for upstream's POSIX `/bin/sh` subprocess
role. The tests package requires the exact runtime, python3 and bash;
shared-library runtime dependencies are
generated by RPM. Source checksum/metadata/tooling validation is separate from
target build/install and physical RPM/SRPM acceptance, which must come from CI.
