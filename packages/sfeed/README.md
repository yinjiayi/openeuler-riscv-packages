# Sfeed 2.4 package

The official HTTPS archive is SHA256 `f9503fe9205a8136f76a9b753c6007abad33e2a516807e416a986723db06e879` (70,093 bytes). The bounded official homepage/release-directory observation selected 2.4; it is not an independently exhaustive latest-release or signing proof. Complete ISC LICENSE plus the bundled Todd Miller ISC notices in strlcat.c/strlcpy.c are preserved and installed.

No upstream source patch is applied. Default `make all` builds thirteen C programs, including the default curses/mono interface. Upstream `make install` installs all four shell scripts, seventeen section-one and two section-five manuals, examples, README files and stylesheet. System compiler/linker flags remain honored. Only standard installation prefixes are relocated to `/usr` and the platform man/doc locations. Internal static helper archives remain internal build artifacts, not a new public library ABI.

This release ships no upstream check/test target or regression fixtures. The noarch tests subpackage contains authored target-only functional QA for all seventeen tools: RSS/Atom and TSV fields, formats, OPML import/export, charset and feed-link discovery, private read-state, default curl/iconv/merge updater via private loopback server (including deduplication and actual fetch failure), plus rendered private curses PTY and normal `q` exit. Build, staged and installed invocations must all pass in target CI. Original default functionality is not replaced with stubs. The xdg-open integration is recommended but not exercised. The unchanged default clipboard-yank integration requires separately supplied xclip, which is absent from the verified target repositories and is therefore not emitted as an unresolvable RPM recommendation; clipboard success is not claimed; external feed network access, exhaustive parser/security validation and native-hardware qualification are not claimed.

No source, compiler, authored QA, local RPM or QEMU execution has occurred on the packaging host. Source/provider admission and trusted recipe validation are distinct from future actual target build, ordinary-DNF installation, physical namespace qualification and publication acceptance. All actual target results remain pending at initial submission.
