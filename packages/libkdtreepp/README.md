# libkdtree++ 0.7.5

`libkdtreepp` is the normalized package-directory identity; the RPM and
discovery identity remains `libkdtree++`. The official component is
`nvmd/libkdtree`, not a different kd-tree library.

The official lightweight tag `v0.7.5` points to
`9b0cbb264393cbd40641256668393ef5bdbfe242`. The commit-pinned source archive
has SHA-256 `b4795c60670f6f6b5c7604804f26adf7e1f8549d4620d8f6c6f384e362f587f2`;
all 46 regular source files were compared with the complete official Git
tree. The tag/commit are unsigned and official releases expose no signature
asset. Full Artistic-2.0 `COPYING` is retained as the RPM license. Locally
authored patches are distributed under Artistic-2.0 with the modified source;
the source and modification descriptions remain available in the SRPM.

This is a noarch header-only package. The original CMake default builds
`test_hayne`, `test_kdtree`, and `test_find_within_range`; its optional Python
bindings default OFF, and no option here disables an originally enabled
feature. Upstream does not register a CTest suite. All three original
programs are built and run, with every original assertion and loop retained.
Debug configuration and final `-UNDEBUG` keep those assertions active.
The original autotools path installs the same six public headers but does
not build/run these programs, and its AC_INIT still says 0.7.1; this recipe
uses CMake and the actual official 0.7.5 header identity instead of publishing
a misleading autogenerated pkg-config version.

Two minimal package-local patches are necessary:

- `0001` checks `end()` before the original `test_hayne` empty-tree lookup
  dereference. It changes only the caller's sentinel handling, not the
  library algorithm, test loops, assertions, or data.
- `0002` retains `include/kdtree++` when installing the six headers. The
  original CMake FILES installation flattened them despite the documented
  `<kdtree++/kdtree.hpp>` contract; autotools already preserves that directory.

The unmodified original three source files are installed under
`/usr/share/libkdtreepp/upstream-original`; the three replay sources retain
all original content except the documented sentinel fix in `test_hayne`.
The validation runner verifies their SHA-256 manifest and recompiles/runs
all three against staged or actually installed public headers. The Hayne
program retains all 700 insertion attempts, 255 unique points and complete
deletion/assertion loop. The range program retains 10,000 generated points
and 1,000 reference comparisons. The main example retains all original
construction, query, copy/assignment, erase, iterator and regression checks.
These results are correctness smoke evidence, not timing/performance claims.

A separate fail-closed downstream consumer covers empty sentinel, insertion,
exact/nearest/bounded/zero-radius queries, inclusive box range,
copy/assignment independence, exact erasure, both iterator directions and
clear. It is additional downstream coverage, not a substituted upstream test
suite. Runtime compiler development dependencies are intentional because
the installed smoke test recompiles the original programs and consumer.

No local upstream, RPM, QEMU or target execution is used. Repository tooling,
metadata/source validation and inert patch checks are local. Actual locked
openEuler riscv64/RVA23 build, original program execution, installation,
installed smoke and physical RPM/SRPM checks remain hosted-CI and merge gates.
